# Alexander Melo — portfolio + blog

A personal site built with **Payload CMS 3** running inside **Next.js**, with **SQLite** for the database and plain **CSS modules** for styling.

## Getting started

You need Node 20.18+ and pnpm (`npm i -g pnpm`).

```bash
pnpm install
cp .env.example .env      # then set PAYLOAD_SECRET to a long random string
pnpm seed                 # fills the database with starter content
pnpm dev
```

- Site: http://localhost:3000
- Admin: http://localhost:3000/admin (the first visit asks you to create your login)

Anything in `[square brackets]` is a placeholder. Edit it in the admin.

## Publishing

The live site at https://melo.codes is plain HTML on GitHub Pages (free). The CMS only runs on your laptop.

1. Run `pnpm dev` and edit content at http://localhost:3000/admin.
2. Run `pnpm export-content`. It writes your published posts, featured projects and profile to `content/site.json`.
3. Commit `content/site.json` and anything new in `media/`, then push to `main`.

`portfolio.db` stays on your machine (it's gitignored), so back it up yourself. The live site only knows what's in `content/site.json`: drafts and logins never leave your laptop.

`.github/workflows/deploy.yml` then runs `pnpm build:static` and publishes the `out/` folder. The build:

- copies `media/` to `public/media/` and writes `public/CNAME` (`scripts/prepare-static.mjs`)
- deletes the Payload admin and API routes, which need a server (CI only, never on your machine)
- prerenders every page, post, topic page and `feed.xml` from `content/site.json` (no database on CI)

The subscribe form posts to [Buttondown](https://buttondown.com). Set `NEXT_PUBLIC_BUTTONDOWN_USER` in `.env` and as a repo secret. If it isn't set, the form is hidden.

### One-time setup

- GitHub repo → Settings → Pages → Source: **GitHub Actions**. Custom domain: `melo.codes`, and tick Enforce HTTPS.
- Repo → Settings → Secrets → Actions: add `NEXT_PUBLIC_BUTTONDOWN_USER`.
- DNS at domain.com for `melo.codes`:
  - `A` `@` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
  - `AAAA` `@` → `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`

## Where things live

```
src/
  payload.config.ts         The CMS: collections, globals, database
  collections/
    Posts.ts                Blog posts (drafts, rich text, code blocks, topics)
    Projects.ts             Portfolio cards
    Media.ts, Users.ts      Uploads and admin logins
  globals/Profile.ts        Your name, intro, experience, contact links
  blocks/Code.ts            The code snippet block used inside posts
  fields/slug.ts            Reusable "slug" field that builds itself from the title
  lib/
    data.ts                 Every database query the site makes
    format.ts               Dates, reading time, headline splitting
  components/               UI pieces, each with its own .module.css
  app/(frontend)/           The public site
    page.tsx                Home
    writing/page.tsx        Blog list with topic filters
    writing/[slug]/page.tsx A single post
    writing/topic/[topic]/  One prebuilt page per topic
    styles.css              Design tokens: colors, fonts, spacing
  app/(payload)/            The admin panel (generated by Payload, don't edit)
  seed.ts                   Starter content
```

## Scripts

| Command | What it does |
| --- | --- |
| `pnpm dev` | Run the site locally |
| `pnpm seed` | Add starter content (`--force` replaces posts and projects) |
| `pnpm generate:types` | Rebuild `payload-types.ts` after changing a collection |
| `pnpm lint` | Check the code for common mistakes |
| `pnpm test:e2e` | Browser tests (run `pnpm seed` first) |
| `pnpm build` | Production build (with a server) |
| `pnpm export-content` | Write published content to `content/site.json` for the live site |
| `pnpm build:static` | Static build for GitHub Pages (runs on CI; see Publishing) |

## Ideas worth knowing (and good interview talking points)

**Server components by default.** Pages and most components run only on the server and send plain HTML. Only two files are marked `'use client'`: the background animation and the nav link (it reads the URL). Less JavaScript in the browser means a faster site.

**Payload's Local API.** `lib/data.ts` calls `payload.find(...)` directly. There's no HTTP request: Payload and Next.js run in the same process and talk straight to the database.

**Access control lives in the collection.** `Posts.ts` says visitors can only read published posts. That rule applies everywhere at once: the REST API, GraphQL and the admin. It's safer than remembering to filter in every query.

**Filters are links, not state.** The topic filter on `/writing` links to `/writing/topic/design`, a page built ahead of time. It works without JavaScript, every view has a link you can share, and the back button works.

**Static export.** Payload is a local editing tool. `pnpm export-content` snapshots published content to JSON, and `lib/data.ts` reads that file in the static build. `generateStaticParams` lists every post and topic, and `next build` turns them into HTML files, so hosting costs nothing.

**Design tokens.** Every color and font is a CSS variable in `styles.css`. Change `--accent` once and the buttons, links and background animation all follow.
